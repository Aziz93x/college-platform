# تشغيل المنصة على حاسوبك بصور الإنتاج

- المرجع: docs/PLAN.md، الخطوة 41؛ ADR-0008
- الأوامر: `pnpm local:up`، `pnpm local:down`، `pnpm local:share`، `pnpm local:run`

تعمل المنصة هنا كما ستعمل على الخادم في أي من خياري الاستضافة (docs/ops/hosting-options.md): Caddy يقدّم `https://localhost` وعنوان حاسوبك على الشبكة المحلية بشهادة من جهة إصدار خاصة به، وخلفه التطبيق والعامل وPostgreSQL على شبكة Docker بلا أي طريق إلى الإنترنت. لا ينشر منفذًا إلا Caddy، وكل خدمة تعود وحدها بعد إعادة تشغيل Docker.

## ما تحتاجه

- Docker Desktop، مع تفعيل «Start Docker Desktop when you sign in» حتى تعود المنصة وحدها بعد إعادة تشغيل الحاسوب.
- Node.js 24 وpnpm، كما في التطوير.
- اتصال بالإنترنت لبناء الصور أول مرة، أو أرشيفات الصور (انظر «التشغيل من أرشيفات الصور» أدناه).

## ملف الأسرار docker/.env

يكتب `pnpm local:up` الملف `docker/.env` من `docker/.env.example`، ويملأ كل قيمة فارغة بقيمة عشوائية جديدة لا يطبعها، ويترك كل قيمة موجودة كما هي. الملف خارج git ولا يُرفع أبدًا.

احفظ نسخة منه في مكان آمن: `AUTH_SECRET` يوقّع الجلسات ويشفّر أسرار التحقق بخطوتين، وكلمات المرور تفتح قاعدة البيانات. إن ضاع الملف وبقيت البيانات، فلن تفتحها القيم الجديدة.

## التشغيل الأول: نسخة شبيهة بالإنتاج

1. قبل أول تشغيل، انسخ `docker/.env.example` إلى `docker/.env` واكتب اسم الكلية واسمها المختصر في `SEED_COLLEGE_NAME` و`SEED_COLLEGE_SHORT_NAME`. يُنشئ أول تشغيل الكلية بهذين الاسمين، ولا يغيّرهما بعد ذلك.
2. شغّل:

   ```sh
   pnpm local:up
   ```

   يبني الصور، ويشغّل الترحيلات بصلاحية مالك الجداول، ثم يبدأ التطبيق بمستخدم قاعدة بيانات لا يملك الجداول. ينتظر حتى تجيب `/readyz`، ثم يطبع العناوين: `https://localhost` وعنوان الشبكة المحلية إن وُجد.
3. أنشئ أول مشرف، مرة واحدة:

   ```sh
   pnpm local:run admin:create --name "الاسم الكامل" --email admin@example.com --employee-number 100001
   ```

   تظهر كلمة مرور مؤقتة مرة واحدة فقط. عند أول دخول يغيّرها المشرف ويفعّل التحقق بخطوتين. يرفض الأمر أي تشغيل بعد ذلك: كل حساب آخر ينشئه المشرفون.

## الثقة بشهادة Caddy

يصدر Caddy شهاداته من جهة إصدار خاصة به، فيحذّر المتصفح حتى تثق بشهادتها الجذرية. الشهادة واحدة للنسخة الشبيهة بالإنتاج ونسخة العرض. لتصديرها والمنصة تعمل:

```sh
docker cp "$(docker ps --quiet --filter label=com.docker.compose.service=caddy)":/data/caddy/pki/authorities/local/root.crt ~/caddy-root.crt
```

احفظ الملف خارج مجلد المستودع، ثم:

- **Windows:** افتح الملف، ثم «Install Certificate» ← «Local Machine» ← «Trusted Root Certification Authorities».
- **macOS:** أضفه في «Keychain Access» إلى «System»، ثم اختر «Always Trust».
- **iPhone:** أرسل الملف إلى الجوال (AirDrop أو البريد) وافتحه، ثم «الإعدادات» ← «تم تنزيل ملف التعريف» ← «تثبيت». بعدها «الإعدادات» ← «عام» ← «حول» ← «إعدادات الثقة بالشهادة»، وفعّل الثقة الكاملة بها.
- **Android:** «الإعدادات» ← «الأمان» ← «التشفير وبيانات الاعتماد» ← «تثبيت شهادة» ← «شهادة CA»، ثم اختر الملف.

## جوال على شبكة الكلية اللاسلكية

على شبكة الكلية، يطبع `pnpm local:up` عنوانًا مثل `https://192.168.1.20`. افتحه من جوال يثق بشهادة Caddy وهو على الشبكة نفسها، فتظهر صفحة الدخول كما ستظهر من خادم داخل الكلية. افتحها أيضًا في نافذة خاصة، وتأكد أن الصفحة لا تتحرك عند وصول خط الهوية.

إن لم تفتح الصفحة، فقد تمنع الشبكة الأجهزة من الوصول إلى بعضها (عزل العملاء). سجّل النتيجة في طلب الموافقة للإدارة العامة. ونجاح الفتح دليل ضعيف على أن خادمًا في قسم آخر من الشبكة سيُفتح، بسبب الشبكات الافتراضية (VLAN).

## وضع العرض: بيانات تجريبية

```sh
pnpm local:up --demo
pnpm local:up --demo --seed 7
```

يشغّل نسخة عرض منفصلة ببياناتها الخاصة (`APP_ENV=staging`)، ويملؤها بالكلية التجريبية. لا تختلط بيانات العرض ببيانات النسخة الشبيهة بالإنتاج أبدًا، ولا تعمل النسختان معًا: أوقف الأولى بـ`pnpm local:down` قبل تشغيل الأخرى.

- تدخل الحسابات التجريبية بكلمة المرور `DEMO_PASSWORD` من `docker/.env`.
- المشرف التجريبي يحتاج رمزًا ثانيًا: استخدم أحد الرموز الاحتياطية في `db/seed/demo/accounts.ts`، وكل رمز يصلح مرة واحدة.
- لتفريغ بيانات العرض والبدء من جديد:

  ```sh
  pnpm local:down
  docker volume rm college-demo_pgdata
  pnpm local:up --demo
  ```

## مشاركة نسخة العرض مع جوال عبر الإنترنت

```sh
pnpm local:share
```

يفتح نفقًا مؤقتًا من Cloudflare (Quick Tunnel، بلا حساب) ويطبع عنوانًا مثل `https://….trycloudflare.com`. يعمل مع نسخة العرض وحدها، ويرفض النسخة الشبيهة بالإنتاج. كل من يعرف العنوان يصل إلى صفحة الدخول، فلا تشاركه إلا مع من يجرّب. أوقفه بـ Ctrl+C.

## الإيقاف وإعادة تشغيل الحاسوب

- `pnpm local:down` يوقف النسخة العاملة، وتبقى بياناتها.
- بعد إعادة تشغيل الحاسوب، يبدأ Docker Desktop وتعود النسخة التي كانت تعمل وحدها. وإن لم تعد، فشغّل `pnpm local:up` من جديد.

## أوامر داخل المنصة

لا تنشر قاعدة البيانات منفذًا، فتعمل هذه الأوامر داخل المنصة على النسخة العاملة:

```sh
pnpm local:run admin:create --name "…" --email … --employee-number …
pnpm local:run seed:demo --seed 42
```

## التشغيل من أرشيفات الصور

هكذا تصل التحديثات إلى خادم داخل الكلية في الخيار أ، على وسيط معتمد وبلا سحب من الإنترنت. على جهاز متصل بالإنترنت:

```sh
compose="docker compose -f docker/compose.yml --env-file docker/.env.example"
$compose build
$compose pull caddy postgres
docker save -o images.tar $($compose config --images | sort -u)
sha256sum images.tar > SHA256SUMS
```

انقل المجلد الذي فيه `images.tar` و`SHA256SUMS`، ثم:

```sh
pnpm local:up --images /path/to/folder
```

يرفض الأمر أي أرشيف لا تطابق بصمته `SHA256SUMS`، ثم يحمّل الصور ويشغّلها دون أي سحب من سجل صور. وهكذا يشغّلها CI في كل طلب دمج.

## اختبار التشغيل

على نسخة عرض جديدة (بعد تفريغ بياناتها كما سبق):

```sh
pnpm exec playwright test --config e2e/stack.config.ts
```

يمرّ على رحلات الدخول والتحقق بخطوتين واستبدال كلمة المرور المؤقتة والخروج والصفحات وفحوص الأمان عبر Caddy. ويفشل أي اختبار يطلب فيه المتصفح شيئًا من خارج المنصة.
