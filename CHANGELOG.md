# Changelog

All notable changes are recorded here. Each entry names the plan step from docs/PLAN.md.

## Unreleased

### Step 04: identity tokens and design-system base

- After cloning, run `pnpm identity:sync` once before `pnpm dev` or `pnpm build`: the fonts and brand assets stay out of git (ADR-0004), and `next/font` reads the fonts at build time.
- `pnpm identity:sync` fetches `Aziz93x/identity-design` pinned at commit `fe72ac24bc089c1e28cdacb70fbd838b252335ad` over HTTPS from raw.githubusercontent.com, so it needs no git, token or system package and runs the same on a laptop, in CI and in the Docker build. `scripts/identity/identity.lock.json` holds the commit, the nine files the platform uses (DIN Next LT Arabic Regular and Medium, the four outlined logos and three element images) with their sha256, and the token mapping. Every file is downloaded and checked before any is written, so a file whose hash differs is refused by name and nothing is written; a file that already matches is skipped, so a second run reports everything up to date. Each download gets 30 s, and a network error, a timeout, a 429 or a 5xx is tried up to three times. Files land under ASCII names: fonts in `src/styles/fonts/`, brand assets in `public/brand/`, both gitignored. A file cut short by a crash no longer matches its hash, so the next run fetches it again.
- The sync renders `src/styles/tokens.css` and `src/styles/token-names.ts` from the bundle's `digital-tokens.json`; both are committed, and CI fails when re-running the sync changes them. `@theme inline` starts with `--color-*: initial`, so Tailwind's default colors (`text-white`, `text-red-500` and the rest) no longer exist and only the semantic roles do. `:root` holds the 36 identity swatches as `--palette-{hue}-{1..6}` plus the light roles; the dark roles sit under `.dark` (`@custom-variant dark`) and are never applied yet. A unit test holds every text pair to 4.5:1 and every UI pair to 3:1 in both themes, which is why muted text uses gray row 2 and the identity's teal and green never carry text.
- One `--alert` token, `#B42318` (6.57:1 on white), with `--alert-foreground` (white) for text on it in both themes. **Pending the owner:** the owner allowed one red outside the identity palette for task states; this step also uses it for destructive buttons, badges and menu items and for invalid and error states, and ships it as a fixed token in the lock file, where section 4 calls the alert color a setting. Both deviations wait for the owner's answer, which Step 23's ADR records (docs/PLAN.md, notes under Step 23). In the dark theme, which ships later, error text and borders in `--alert` miss the contrast bar on the dark background (1.28:1).
- Section 4's status colors are only the alert so far: success, warning and info roles come with the task states in Step 23, and the identity gradient with the login page in Step 6 (notes under both steps).
- Fonts load through `next/font/local` with `font-display: swap` and an Arial-based metric-matched fallback, then Tahoma and sans-serif. Headings are Medium through a base rule and body text Regular; `--font-weight-*` offers only those two weights, the two files the identity ships. `src/styles/theme.css` holds the scales without colors: rem type sizes with body line height 1.7, 4 px spacing, radii, elevation mixed from the darkest gray, motion of 120 to 200 ms and a reduced-motion rule; tables use tabular numbers.
- `check:hardcode` also rejects `rgb()`, `rgba()`, `hsl()`, `hsla()`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()` and `color()` outside `tokens.css` (`color-mix()` of tokens stays allowed), CSS named colors (in a Tailwind arbitrary value such as `bg-[red]`, as a whole string such as `color: "red"` or `fill="white"`, and in a CSS declaration), and `prefers-color-scheme` anywhere in `src/`.
- CI and the Docker build run `pnpm identity:sync` before `pnpm build`, and both copy `public/` next to the standalone server, which now serves `/brand/*`. CI builds with `APP_URL`, `DATABASE_URL` and `SMTP_URL` empty, as the Docker build has them, so a build that reads the environment or the database fails in the checks job too. `.local/` (screen captures) stays out of the Docker build context.
- `<html lang dir>` comes from the new college setting `locale.language` (a Zod enum of the languages with a catalog, `ar` by default), with the direction derived from it through `Intl.Locale#getTextInfo()`, so there is no separate direction setting and the two cannot disagree. next-intl's request config (`src/i18n/request.ts`) reads `locale.language` and `locale.timeZone` for the deployment's college (the first by creation) on every request, so dates format in the college's time zone, not the server's. The root layout waits for that read behind `await connection()` and `export const instant = false`, so no route gets a static shell and every page needs the database: ADR-0007 (proposed) records this and the cached alternative for the owner. `pnpm seed:demo` stores the language for the demo college. A unit test renders the root layout with another language to prove `lang` and `dir` come from the setting.
- `src/i18n/` sits beside `platform/`, not inside it as section 2's layout shows, because it reads module settings; dependency-cruiser keeps `src/components`, `src/i18n` and `src/styles` out of `platform/`, `src/i18n` out of `modules/`, and the design system out of a module's `domain/` and `server/`.
- next-intl with `messages/ar.json`, typed keys, the Radix `DirectionProvider` and the Sonner toaster with its region named from the catalog. Client components receive only the message namespaces they read: the root layout passes `ui`, and `/design` adds `design`, so a route's payload does not carry the whole catalog. `latinDigits()` in `src/platform/validation/digits.ts` is the shared Zod preprocessor that turns Arabic-Indic (U+0660 to U+0669) and extended Arabic-Indic (U+06F0 to U+06F9) digits, and the Arabic decimal (U+066B) and thousands (U+066C) separators, into Latin ones, for every input from Step 6 on.
- 26 shadcn/ui primitives in `src/components/ui/`, copied from shadcn-ui/ui at commit `ba1503c64472b82256d9de95e2e62c5901a38e8b` (`apps/v4/registry/new-york-v4/ui`; the CLI registry is blocked here), with `cn` in `src/components/ui/cn.ts` and `components.json` pointing at that commit's schema. They are restyled with the identity tokens only: destructive and invalid states use `--alert`, hover and selected surfaces use `muted` because the identity's teal and green never carry text, and inactive tabs and avatar initials keep full foreground for contrast. `shadcn migrate rtl` and hand edits give logical properties: sheets open from `start` or `end`, the switch and progress bar mirror, select offsets stay physical, the calendar's month arrows turn around right to left, and the calendar takes its direction from the Radix DirectionProvider and its month names and labels from react-day-picker's locale for `locale.language`. Overlays animate on `--duration-fast` and `--duration-slow`; sonner no longer uses next-themes. Variants and sub-exports nobody uses are removed: button sizes other than `default` and `icon`, the badge `ghost` and `link` variants, the tabs `line` variant and the small switch and select trigger.
- Touch targets of 44 px (section 4): on a touch screen (`pointer: coarse`) buttons, inputs, select triggers, tabs, calendar days and menu, select and command items are at least 44 px high, and checkboxes, radios, switches and the dialog and sheet close buttons get an invisible 44 px hit area from the `touch-hit-area` utility; radio rows are 44 px apart there. An end-to-end test on the iPhone project checks every enabled control on `/design` and in each overlay. On a mouse the primitives keep shadcn's sizes.
- No BeUI piece is added: BeUI has no identifiable package or repository, and vaul (the bottom sheet) and Sonner (the toast stack) already cover the two motion pieces the plan names (ADR-0001, amended). Springs for sheets and drawers are not done: the sheet eases on `--duration-slow` and the drawer keeps vaul's 0.5 s curve (docs/BACKLOG.md).
- `/design` shows the color roles in both themes (from the generated `src/styles/token-names.ts`), the type scale, spacing, radius, elevation, motion, the identity elements from `/brand/` (never the logo) and every primitive in its states, each overlay from a labelled trigger, with every word from `messages/ar.json`. It is served while `APP_ENV` is `local` only. Elsewhere `src/proxy.ts` answers 404, because under Cache Components a `notFound()` in the route streams after a 200 status, and the page refuses as well. It has a loading skeleton and an error state.
- The reduced-motion rule is `!important`, so it also stops vaul's drawer transition.
- `e2e/design.spec.ts` checks the 26 primitives, each overlay's role, name and Escape, the toast, axe (WCAG 2.2 AA, no serious or critical issue) on the page and with each overlay open, the motion tokens and reduced motion, the Arabic-Indic digits in the form, the heading and text weights, that `/brand/*` is served as PNG and the identity font loaded, and the direction and language of the overlays, the calendar's arrows included. axe takes joined Arabic letters for icon ligatures and skips their contrast, so the test swaps them for Latin letters before it runs.
- `e2e/identity-font.spec.ts` proves the identity font through Chromium's DevTools protocol: a specimen with every Arabic letter, the hamza forms, Arabic punctuation and Latin digits renders entirely in DIN Next LT Arabic at 400 and at 500, each weight from its own file, and a joined word measures differently from its letters set apart with U+200C. With the font files held back a second, the fallback paints first and the swap shifts the layout of `/design` by less than 0.05.
- Visual baselines of `/design` at 390, 768 and 1440 px (`e2e/design.visual.spec.ts`, tagged `@visual`, desktop project only) come from CI's pinned Chromium, never from a laptop. Before each capture the test waits for the streamed content and proves the brand elements and the identity font loaded, so a broken render never becomes the reference; the brand elements are masked, so the committed baselines hold no brand asset (ADR-0004). A run with a missing baseline writes it and fails; CI uploads only the new files and the `baselines` job commits them to the pull request's branch, never replacing a committed one. To update a baseline, delete it and push; then push again, since the job's own push starts no run. Runs outside CI skip `@visual` tests, because a laptop's Chromium and fonts differ.
- `pnpm e2e:screens` captures routes for the UX reviews: `SCREENS_ROUTES` (separated by spaces or commas, default `/`), `SCREENS_OUT` (default `.local/screens`) and `SCREENS_ROLES` (only `anonymous` until Step 6 adds sign-in) give `<out>/<role>/<route-slug>-<width>.png` at 390, 768 and 1440 px, the 390 px capture on an emulated phone with touch. Each capture waits until every streamed Suspense boundary shows its content, every image has loaded and the fonts are ready, so it never captures a loading skeleton; two routes that would share a file name are refused. It has its own Playwright config on the same web server, and `pnpm test:e2e` never runs it.

### Audit 1: steps 1-3

- `check:hardcode` catches role-name checks written on one line. On a line that mentions `role`, it flags a role-like string literal (one with no dot or slash, so permission keys such as `"roles.assign"` and paths pass) that is compared, searched for with `.includes`, `.has`, `.startsWith` or `.endsWith`, passed to `hasRole()` or a Drizzle comparison (`eq`, `ne`, `inArray`, `notInArray`, `like`, `ilike`), listed in an assigned array or compared in SQL (`= 'x'`); and an array or `Set` literal searched with `.includes(` or `.has(`. It also flags a `case "x"` in the innermost `switch` on a role, a `SCREAMING_CASE` name with a `ROLE` or `ROLES` part, and an `enum` named after roles. docs/reviews/audit-03.md lists the forms it misses.
- `check:boundaries` makes `domain/` an allowlist: it imports only its own module's `domain/` files, `zod`, `vitest` and types from a module's `index.ts`, so npm I/O packages such as `pg`, `pg-boss`, `drizzle-orm` and `next/headers` fail too, in tests as well.
- `audit_events` is append-only in the database: migration `0001_audit_events_append_only.sql` adds triggers that reject `UPDATE`, `DELETE` and `TRUNCATE`. They stop mistakes, not the table owner, which is the app's own database user.
- CI runs the Playwright smoke test against the standalone production build (`node .next/standalone/server.js`) instead of the dev server.
- ADR-0004 (proposed): the repository stays public, and licensed or non-public brand assets never enter git. `.gitignore` ignores `*.woff`, `*.woff2`, `*.ttf`, `*.otf` and `public/brand/`, a unit test fails when a font or brand file is tracked, and docs/PLAN.md Step 4 carries the rule.
- docs/PLAN.md notes under Step 4 (fonts, color guard gaps, `public/` copy) and Step 11 (the triggers and the retention purge); docs/BACKLOG.md lists minors 1-5 for lead review A.

### Step 03: database, jobs and platform core

- Drizzle ORM on PostgreSQL through `pg`, with a lazy pool so `next build` needs no database. Each module owns its tables: `colleges` (org), `settings` (settings) and `audit_events` (audit), in the first migration `db/migrations/0000_platform_core.sql`.
- `pnpm db:generate` writes SQL to review in the PR, and CI fails when a `schema.ts` changed without it; `pnpm db:migrate` applies the SQL and then installs or upgrades the pg-boss schema, writing no row on a re-run; `pnpm db:seed` creates the one college from `SEED_COLLEGE_NAME` and `SEED_COLLEGE_SHORT_NAME` only when none exists, also when two runs start together.
- `pnpm seed:demo [--seed <0 to 2^32 - 1>]`: a deterministic demo seed (mulberry32, default 42) that is safe to run twice and refuses to run when the new `APP_ENV` (`local`, `staging` or `production`, default `production`) is `production`, before it connects.
- A settings registry in code (key, scope, Zod schema, default) with `locale.timeZone`, which accepts any IANA name or alias that `Intl` can format with, and `getSetting(key, { collegeId })`, which returns the stored value parsed with the key's schema or the registered default. Every setting is college-scoped for now.
- `worker/index.ts` runs pg-boss: a `heartbeat` job scheduled every minute, and a graceful stop on SIGTERM or SIGINT that waits up to 8 s for running jobs, then exits 0, or exits 1 when the stop fails or is still running at 9.5 s, before Docker's SIGKILL. It logs `worker started` only once those signal handlers are installed. A failed start is logged as JSON and exits 1.
- pino JSON logs on stdout; `src/proxy.ts` gives every request a new `x-request-id`, replacing any the client sent, and returns it on the response. Server code logs through `getRequestLogger()`, which adds it to each line, and `onRequestError` in `src/instrumentation.ts` logs every server error Next reports with it. Worker lines carry the queue and job id instead. `/healthz` reports the process alive; `/readyz` checks the database and the queue and answers 503 when either fails.
- `check:boundaries` also checks `worker/` and `db/`, which use a module only through its `index.ts`.
- Integration tests on Testcontainers PostgreSQL inside `pnpm test`, with a database per test file cloned from a migrated template (ADR-0003). CI sets `APP_ENV=local`, migrates the database and loads `pnpm seed:demo` before the end-to-end tests.
